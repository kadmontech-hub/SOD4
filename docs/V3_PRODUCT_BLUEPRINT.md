# SØD Visual MVP V3 — Product Blueprint

## Objective

V3 is both an MVP and a navigable mockup of the intended final product. It does not pretend every asset, model, text or inference is final. It demonstrates the final hierarchy, interaction model and transformation loop with replaceable placeholders.

## Product decisions implemented

### 1. Greater scale

- Expanded desktop and ultrawide layout system.
- Fluid type and spatial proportions.
- Monumental hero moments for Hub, Elementos 33, individual Elements, Codes and Observatory.
- Purposeful use of negative space instead of small centered dashboard containers.

### 2. Less permanent UI

- Global navigation reduced to Hub, Explore, Personal Archive and Settings.
- Full world navigation is progressively disclosed through an overlay.
- The Hub removes fixed left and right panels.
- Needs are shown through a compact dock and contextual drawers.
- Daily message and journey traces remain hidden until requested.

### 3. Better spatial hierarchy

- The Hub prioritizes world, core and human need.
- Universes are grouped by need: understand, cultivate, direction and observe.
- Cards are replaced with gates, artifacts, archive pieces, relics or spatial stages where possible.

### 4. Monumental Elementos 33

- The five elements are presented as forces, not categories.
- Each element receives a full world hero.
- The 33 pieces are organized by cognitive depth instead of one equal grid.
- Velo, Remez, Derash, SØD and SØD² have different visual scales.
- SØD² is presented as a singular origin piece.

### 5. More sophisticated SØD core

- The Canvas core has multiple orbital layers, light particles, geometric shell and breathing.
- The functional transformation experience uses visual core states: listening, processing, mapping, witnessing, discovery, evidence and integration.

### 6. First functional transformation cycle

The `/experiencia` route implements:

1. Human need entry.
2. Scripted SØD response through the current API adapter.
3. Cognitive separation: fact, interpretation, emotion and uncertainty.
4. Three deepening questions.
5. Before/after transition verification.
6. Discovery of a pre-existing canonical Seed.
7. Acceptance of a practical application.
8. Explicit consent to preserve the moment.
9. Creation of a private SØD Code.
10. Persistent visible change in Observatory.

## Constitutional constraints

- Seeds are never generated.
- A discovered Seed is selected from the canonical data set.
- Codes require a user-confirmed transition.
- The user controls whether a Code is preserved.
- Codes and Seeds remain visually and conceptually separate.
- The Observatory interprets relationships rather than displaying productivity scores.
